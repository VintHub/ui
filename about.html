Everything you always wanted to know about CVEs*

*but were afraid to ask

Vinthub, the Vulnerability Intelligence Hub is a platform designed to provide comprehensive vulnerability intelligence without the need for subscriptions to proprietary databases. VintHub puts together data from a suite of public and trusted cybersecurity sources, including the National Vulnerability Database (NVD), CISA's Known Exploited Vulnerabilities (KEV) catalog, FIRST EPSS, the CVE Program, Red Hat VEX and GitHub GHSA.

Tailored for both offensive and defensive security practitioners, the tool centralizes prioritization metrics while providing immediate access to public exploits and proof-of-concept (PoC) code.


Key intelligence provided for each CVE:

  • Severity and CVSS: severity, reported both as in score, level and CVSS vector.
  • Affected vendors and products: list of vendors and products, plus a functionality to check if a given version is vulnerable
  • SSVC: AThe Stakeholder-Specific Vulnerability Categorization (SSVC) framework, automatically calculating actionable remediation priorities (e.g., Track, Attend, Act).
  • BOD 26-04 SLA: Pre-calculated BOD 26-04 SLAs.
  • Public exploit/PoC data: Crawls best of breed public repositories, including GitHub PoC archives, Exploit-DB, Metasploit and Nuclei, to correlate vulnerabilities with existing proof-of-concept code.
  • CWE/CAPEC: CWE/CAPEC associated to CVEs.
  • News: Mentions of the CVE in public news outlets.

SSVC is shown even when official sources don't provide it. Where is that data coming from?

When an official SSVC is not available, it is calculated dynamically based on the data from other sources:

Exploitation Field

• If the CVE is in the CISA KEV catalog, it is set to Active (A).
• Else if there is at least one PoC URL, it is set to PoC (P).
• Otherwise, it defaults to None (N).

Automatable Field

The CVE is marked as Yes (Y) if the CVSS metrics match:
Attack Vector: NETWORK + Privileges Required: NONE + User Interaction: NONE + Attack Complexity: LOW.
All other conditions result in No (N).

Technical Impact Field

Marked as Total (T) if Confidentiality Impact: HIGH AND Integrity Impact: HIGH.
Otherwise, it is marked as Partial (P).

Your SSVC Exploitation field sometimes differs from the one provided by CISA/NVD. Why?

Whenever we get to know that a PoC is available and SSVC provided by CISA reports Exploitation as None, we update it to PoC to better reflect reality. For the same reason, whenever we get to know that a CVE is listed in KEV and SSVC provided by CISA/NVD has Exploitation set to None or Poc we update it to Active.

Sometimes official sources provide more than one CVSS score for a single CVE, but in the web UI you are only showing one.

Sometimes less is more. To avoid noise, the tool prioritizes the official primary metric from the NVD and favors the most recent CVSS version (e.g., CVSS v4.0 or v3.1 over v2.0). The API endpoint shows all available scores, and there's also a functionality in the UI to view the full list of scores.

Where are you getting your PoCs from?

Currently, PoC research is aggregated from the following sources:

  • NVD Reference Tags: Specific links tagged as "Exploit" within the official NVD record.
  • CISA ADP: Specific links tagged as "Exploit" within the official CISA ADP record.
  • Exploit-DB: Entries from the OffSec exploit database.
  • Metasploit: Modules from Rapid7 Metasploit.
  • Nuclei: Templates from ProjectDiscovery Nuclei.
  • GitHub: The awesome nomi-sec/PoC-in-GitHub repository.

Are you checking if the PoCs are safe?

Absolutely not. These links are provided for research and intelligence purposes only. You should never execute code found in these repositories without first manually auditing the content in a secured, isolated environment.
