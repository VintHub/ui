VintHub REST API Reference

Two read-only JSON endpoints: consolidated intelligence for a single CVE, and the CVE news feed for a single day.

Overview

EndpointPurpose
GET cve.vinthub.io/{year}/{cve_id} Full intelligence record for one CVE: scores, SSVC, BOD SLA, KEV status, PoCs, references and news.
GET news.vinthub.io/{year}/{month}/{date} All CVEs that appeared in the news on a given day, with the articles that mention them.

Both endpoints are plain GET requests that return application/json; charset=utf-8.

CVE Intelligence Lookup API

GET https://cve.vinthub.io/{year}/{cve_id}

Returns one consolidated JSON record for a CVE: CVE.org and NVD metadata, CVSS, EPSS, CWE, SSVC decisions, BOD SLA, CISA KEV status, public PoCs, references and recent news.

Path parameters
NameTypeDescription
yearstringFour-digit year from the CVE ID, e.g. 2026.
cve_idstringFull CVE ID in upper case, e.g. CVE-2026-123890. The year in the path must match the year in the ID.
  • ✓ Input: year (YYYY) and CVE ID
  • ✓ Output: one JSON object with everything known about the CVE 
curl -X GET "https://cve.vinthub.io/2026/CVE-2026-123890" \
  -H "Accept: application/json"
import requests

cve_id = "CVE-2026-123890"
year = cve_id.split("-")[1]

response = requests.get(f"https://cve.vinthub.io/{year}/{cve_id}", timeout=10)
response.raise_for_status()
data = response.json()

print(data["title"])
print("CVSS:", data["cvss"][0]["baseScore"])
print("EPSS:", data["epss"]["score"])
print("SSVC (High):", data["ssvc"]["decisions"]["Mission & Well-being - High"])
print("In CISA KEV:", data["cisa_kev"]["in_cisa_kev"])
print("BOD SLA:", data["bod_sla"]["public"])
print("PoCs found:", len(data["pocs"]))

Response fields

The response is a single JSON object. Dotted names such as epss.score refer to nested fields, and [] marks an array. Some fields can be empty when nothing is known for a CVE (for example capec is an empty array in the sample above), so handle missing or empty values.

FieldTypeDescription
cve_idstringThe CVE identifier.
statusstringRecord state, e.g. PUBLISHED.
published_date.nvdstringPublication date in NVD (YYYY-MM-DD).
published_date.cveorgstringPublication date on CVE.org (YYYY-MM-DD).
titlestringShort title of the vulnerability.
descriptionstringFull description. May contain newline characters.
productsstringComma-separated list of affected product names.
affected.cna_affected[]arrayAffected products as reported by the CNA. Each item has vendor, product, defaultStatus and versions[] (status, version, optional lessThan, versionType).
affected.nvd_cpes[]arrayNVD configuration entries. Each has nodes[] with operator, negate and cpeMatch[] (vulnerable, CPE 2.3 criteria, and optional version bounds such as versionStartIncluding and versionEndExcluding). Nodes can be nested under an AND operator.
cvss[]arrayOne entry per scoring source: version, vectorString, baseScore (0.0 to 10.0) and source.
epss.scorenumberEPSS probability of exploitation in the next 30 days, from 0 to 1.
epss.percentilenumberShare of all scored CVEs with an EPSS score at or below this one, from 0 to 1.
cwe[]arrayWeakness types: id (e.g. CWE-288) and description.
capec[]arrayRelated CAPEC attack patterns. Empty when none are mapped.
ssvc.factorsobjectSSVC inputs: Exploitation, Automatable and Technical Impact.
ssvc.decisionsobjectSSVC decision per mission and well-being impact level, keyed Mission & Well-being - Low, - Medium and - High. Values are SSVC outcomes such as Track, Track*, Attend and Act.
bod_sla.publicstringRemediation deadline under CISA BOD 26-04 for public-facing assets, e.g. 3 Days + Forensic Triage.
bod_sla.internalstringRemediation deadline under CISA BOD 26-04 for internal assets.
bod_sla.factorsobjectInputs behind the SLA: in_cisa_kev, automatable and technical_impact.
pocs[]array of stringsURLs of public proof-of-concept code and exploit write-ups.
references[]array of stringsVendor advisories and other reference URLs.
cisa_kev.in_cisa_kevbooleantrue if the CVE is in the CISA Known Exploited Vulnerabilities catalog.
cisa_kev.added_datestringDate the CVE was added to KEV (YYYY-MM-DD).
cisa_kev.ransomware_campaign_usebooleantrue if CISA marks the CVE as used in ransomware campaigns.
news[]arrayNews articles about the CVE, newest first. Each has title, link and date (YYYY-MM-DD).

Daily Threat News Feed API

GET https://news.vinthub.io/{year}/{month}/{date}

Returns every CVE that was covered in the news on the given day, together with the articles that mention it.

Path parameters
NameTypeDescription
yearstringFour-digit year, e.g. 2026.
monthstringTwo-digit month with a leading zero, e.g. 10 or 03.
datestringFull date as YYYY-MM-DD, e.g. 2026-10-08.
  • ✓ Input: year (YYYY), month (MM), date (YYYY-MM-DD)
  • ✓ Output: an object mapping each CVE ID to its news articles for that day
  • ✓ Tip: take a CVE ID from this feed and look it up with the CVE Intelligence API 
curl -X GET "https://news.vinthub.io/2026/10/2026-10-08" \
  -H "Accept: application/json"
import requests

date_str = "2026-10-08"
year, month, _ = date_str.split("-")

response = requests.get(f"https://news.vinthub.io/{year}/{month}/{date_str}", timeout=10)
response.raise_for_status()

for cve_id, articles in response.json().items():
    print(f"{cve_id} ({len(articles)} articles)")
    for article in articles:
        print(f"  - {article['title']}: {article['link']}")

Response fields

The response is a single JSON object. Its keys are CVE IDs, and the order of keys is not significant. Older CVEs can appear too, for example when one is added to CISA KEV that day.

FieldTypeDescription
{cve_id}arrayKey is a CVE ID such as CVE-2026-21589. The value lists the articles published that day about this CVE. One article can appear under several CVE IDs.
{cve_id}[].titlestringHeadline of the article.
{cve_id}[].linkstringURL of the article. Official sources such as CISA KEV entries are included as well.

Articles in this daily feed carry no date field because the date is already in the URL. The news[] array in the CVE Intelligence API does include one per article.
